## Как писать страницу руководства

Страница описывает часть приложения так, чтобы новый разработчик мог ей пользоваться, не читая весь код.

```markdown
# <Фича>

Одно-два предложения: что делает фича и для чего.

## Где лежит
Дерево папок фичи с пояснением каждой важной папки и файла.

## Публичный API
Что экспортирует `index.ts`: абстрактные классы, типы, компоненты (селектор, входы, выходы), функции `provideXxx()`, токены расширения. По каждому — одна строка назначения.

## Как пользоваться
Короткие примеры кода для типовых задач: получить данные, встроить компонент, обработать ошибку.

## Как расширить или заменить
Как подменить реализацию через DI, как подключиться к точке расширения, что поменять при добавлении поля.

## Тесты
Где лежат тесты фичи, какой контракт у репозитория, какие фейки доступны.

## Подводные камни
Неочевидное: ограничения SSR, правила доступа, особенности PocketBase.
```

Правила:

- Пиши о том, что есть в коде сейчас, а не о планах. Если код меняется — страница меняется в том же коммите.
- Примеры кода должны быть рабочими и короткими; полный код — ссылкой на файл.
- Не дублируй `architecture.md` и `data-model.md`: ссылайся на нужный раздел.
